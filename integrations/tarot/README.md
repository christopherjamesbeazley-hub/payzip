# Paid one-card reading
Apply tarot-site.patch to the root of the supplied tarot-experience v1.1.0 site using git apply. The Payzip Netlify build still publishes public/. The tarot site retains its own Netlify functions and build settings.

For a sandbox rehearsal, use separate test deployments and a test database. Run schema.sql once on Supabase Postgres. On Payzip configure TAROT_SITE_ORIGIN (the exact HTTPS tarot host with no trailing slash), TAROT_PRICE_CENTS and the usual Stripe test checkout key. On the tarot site configure PAYZIP_ORIGIN (sandbox Payzip origin), matching TAROT_PRICE_CENTS, TAROT_STRIPE_READ_KEY (same Stripe account and mode, Checkout Sessions read), SUPABASE_URL and SUPABASE_SERVICE_ROLE_KEY as function secrets. Use a dedicated project. Keep AI keys unset. Use Netlify's build workflow so it packages functions.

Open the tarot home page and start a purchase. Complete Stripe test checkout. Reveal the card, refresh, and open the same return URL in two tabs. Both tabs must show identical results, with one database row for the session. A private window must be refused. Retry after pending payment settles. Cancelled payments must grant nothing. Test using canonical origins so the HttpOnly cookie returns to its issuing host. The result can be revisited using the return URL in the same browser while the cookie survives. Refund and dispute revocation, email recovery and paid AI generation are outside this first version.
